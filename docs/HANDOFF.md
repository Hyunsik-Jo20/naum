## ★★★ 이번 세션 2차(2026-09-22) — 활력징후 **학년·성별 자동 기준**
> 나음은 **초등학교**에서 쓰인다. 기존 기본값은 "학령기 일반"이라 학년·성별 차이를 못 봤다.
> 키오스크에서 학생이 고른 학년·성별이 방문(`visit.grade`/`visit.sex`)에 남으므로, 그걸로 참고범위를 자동 선택한다.

- **밴드 구조**(`types.ts VitalBand`, `data/vitals.ts`): 항목마다 `bands[]` — `{fromGrade, toGrade, sex?, low, high, low2, high2}`.
  맞는 밴드가 있으면 항목의 기본 `low/high`를 덮어쓴다. **학년 0 = 교직원(성인)**. 같은 학년에 성별 줄과 공통 줄이 다 있으면 **성별 줄이 우선**.
- **기본값(초등)**
  | 항목 | 학년별 차이 | 근거 |
  |---|---|---|
  | 혈압 | **학년·성별 12줄 + 성인** (1학년 84~106/50~68 … 6학년 남 90~113/50~75, 여 90~114/50~75) | 상한 = AAP 2017 연령·성별 선별 혈압값(90 백분위), 하한 = PALS 저혈압 기준(1~10세 70+2×나이, 10세~ 90). 이완기 하한은 소아 표준이 없어 50(성인 60) |
  | 맥박 | 초1~6 75~118 / 성인 60~100 | AHA PALS 안정 시 심박수(학령기 6~12세) |
  | 호흡수 | 초1~6 16~25 / 성인 12~20 | PALS 학령기 18~25 — 안정 시 오경보를 줄이려 하한만 16으로 완화 |
  | 체온·산소포화도 | 없음(연령 무관) | 36.0~37.4℃ / 95~100% |
  - 학년→나이: **초1 = 만 7세 … 초6 = 만 12세**(`AGE_OF_GRADE`). 학년도 중 대부분을 그 나이로 보내므로 이 대응을 썼다.
- **입력 화면**(`VitalsModal`): 상단에 "참고범위는 **3학년 여 기준**으로 자동 적용됩니다", 항목마다 그 학생 기준 범위를 작게(`\.vit-hint`) 표시. 경고 문구·플래그·placeholder 전부 밴드 적용값 기준.
- **항목 편집**(`VitalsEditModal`): 항목마다 "학년·성별 기준 N줄"을 펼쳐 줄 추가/삭제/수정. 밴드가 없는 항목은 기존처럼 단일 범위. 근거 한 줄(`source`)도 함께 보여 준다.
- **기존 학교 이관**: 이미 항목을 편집해 저장한 학교는 밴드가 없다 → 편집 화면 상단에 "초등 학년·성별 기본 기준이 추가되었습니다 / **적용하기**" 안내. 누르면 **이름·단위·기본범위는 그대로 두고 밴드만** 입힌다(`withDefaultBands`). 안 눌러도 종전 동작 유지.
- ⚠ **진단 기준이 아니다.** "확인이 필요한 값"을 짚는 표시일 뿐이고, 학교가 자기 지침으로 조정할 수 있게 전부 편집 가능하게 뒀다.
- **성별 파싱 버그의 실제 범위 — 정정(2026-09-22 사용자 확인)**: "기존 업로드분은 전원 남으로 굳었다"는 과장이었다.
  수정 전 코드는 `sex: find('성별','sex')` + `/여|f/i.test(값) ? '여' : '남'` 이라서,
  **머리글이 `성별`이고 값이 남/여인 평범한 파일은 원래도 정확히 읽혔다.**
  전원 '남'이 되는 건 ① 머리글이 `성 별`·`성별(남/여)`·`남녀` 같은 변형 ② 값이 NEIS 숫자코드 `1`/`2`
  ③ 성별 열 자체가 없음 — 이 경우들뿐이다. 그래서 **무조건 재업로드가 아니라 확인 후 필요할 때만** 하면 된다.

## 6-1. 최근 추가(2026-07-10) — relay 재연결·오프라인 큐 보강
- **오프라인 아웃박스 무유실·재시도 고도화**(`data/offline.ts`): 큐 항목을 `{id,op,tries}`로 관리(구버전 bare op 자동 마이그레이션). ① 온라인+큐 빈 경우 즉시 시도, 실패하면 큐로(유실 방지) ② 실패 op는 **버리지 않고 지수 백오프**(1→2→4→8→16→30s) 재시도, **순서 보존**(실패 op 뒤는 대기) ③ `MAX_TRIES(8)` 초과 op만 **dead-letter**(`naum.outbox.dead`)로 격리해 큐 안 막힘 ④ 재시도 트리거 = `online`+`visibilitychange`+주기 20초 ⑤ id 기반 제거로 flush 중 동시 append 유실 없음. 검증: 상태기계 시뮬(순서·무유실·백오프·dead-letter·동시append) 전부 통과 + 실모듈 정규화/마이그레이션 확인.
- **쓰기 실패 전파**: `supabaseBackend.createVisit/patchVisit/deleteVisit`·`supabaseRelay.emitClass/emitStudent`가 에러를 삼키던 것 → **throw로 전파**(큐가 실패를 감지·재시도). `createVisit`는 재시도 멱등(23505 중복키=성공 간주), 링크·삭제 링크는 베스트에포트.
- **Realtime 재연결 catch-up**: `subscribeClass/subscribeStudent`가 `SUBSCRIBED` 재도달 시 `onChange` 재발화(끊긴 사이 이벤트 재조회) + `online`/`visibilitychange` 시 재조회(소켓 절전 stall 대비). 수신 loader는 재시도 중복 이벤트 **dedupe**(토큰+시각+종류). 콘솔(`visits.tsx`)도 재연결/복귀 시 방문 재조회 병합(기존 로컬 유지, 없는 것만 추가 → 미업로드 되돌림 방지).

## 6-4. 보안 점검(2026-07-10) — 저위험 조치 완료 + 남은 항목
**완료(코드/설정, `api/proxy.js`·`api/health.js`)**:
- **입력검증**: proxy `endpoint`를 `^[A-Za-z0-9_]+$` 화이트리스트(경로 조작 차단), `svc`는 TARGETS만.
- **인증/오남용**: proxy에 **Origin/Referer 검사**(동일출처·로컬만; 헤더 없으면 통과→앱 무중단)로 타 사이트 핫링크 차단. `health`의 `hasKey` 노출 제거.

영향 범위: 보건일지·교장 보고의 과거분, 완료 카드, 인계서 출력, 요보호 지정(`Student.care`는 명부에 붙어 있어 재업로드 시 소실).

**사용자가 제시한 실마리**: NEIS에서 **이전학년도 ↔ 현재학년도 변동 데이터**를 내려받을 수 있다.
→ 그 파일이 `(작년 학년·반·번호) → (올해 학년·반·번호)` 대응표가 되므로, **id 재매핑**으로 과거 기록을 살릴 수 있다.

**설계안(확정 대기)**
1. **명부에 학년도(`year`)를 붙이고 이전 명부를 아카이브**(`naum.roster.{year}`, secureStore 암호화 유지).
2. 과거 방문 이름 복원은 **방문 시각이 속한 학년도의 명부**로 조회 → `findStudent(id, atMs)` 확장.
3. 새 학년도 명부 적용 시 **승급 마법사**: NEIS 변동 파일을 함께 올리면 `old id → new id` 대응표를 만들고
   - 요보호 사유·보호자연락처를 새 학생으로 **이월**
   - 진급 N명 / 신입 N명 / 졸업·전출 N명 **요약을 보여 주고 확인받은 뒤** 적용
4. 변동 파일이 없으면 **이름+성별 매칭**으로 대응표를 추정하고, 애매한 건만 손으로 확정.

**먼저 정해야 할 것**
- NEIS 변동 데이터의 **실제 열 구조**(샘플 필요) — 위 1~4의 구현 방식이 여기서 갈린다.
- 아카이브 명부를 **몇 년치** 보관할지(개인정보 보유기간 — 학교 방침).
- 전학생·중도 편입은 변동 파일에 어떻게 찍히는지.
